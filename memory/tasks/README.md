# Task Memory

Create one file per meaningful implementation task.

Recommended naming:

```txt
task-01-repository-baseline.md
task-02-domain-core.md
task-03-supabase-schema-and-rls.md
```

Use `_template.md` for each task.

## When To Update

- At task start, copy the template and fill in scope.
- During work, update progress only at meaningful checkpoints.
- Before handoff, fill QA, acceptance criteria status, review notes, and follow-ups.
- After review, record requested changes and final outcome.

## What Belongs Here

- Task progress.
- Verification commands and results.
- Acceptance criteria state.
- Review findings.
- Decisions made during the task.
- Follow-up debt or ideas discovered during the task.

## What Does Not Belong Here

- Secrets.
- Raw financial files.
- Long command logs.
- Full copied specs.
- Personal notes unrelated to the task.
